# 듣기 해설 대본 (`narration.ts`)

페이지 머리말의 듣기 버튼(`ListenButton`)이 읽는 대본. 형식(`ScriptLine` · `Pause`)은 `packages/ui/src/doc/listen/script.ts`, 발음 사전은 같은 폴더의 `speech.ts`가 정답이다. 모드 이름은 화면에서 '해설' · '본문 그대로'이고 '강의'라고 쓰지 않는다(내부 id `'lecture'`만 유지).

## 내용

- **사실은 페이지 컴포넌트 그대로, 말투만 바꾼다.** 새로 더하는 것은 연결 문장과 자문자답 질문뿐이다
- **`text`는 자막으로 보이므로 화면 문장과 어긋나지 않게 쓴다.** 화면 문장을 고치면 대본도 같이 고친다
- 위치어("여기", "왼쪽")만으로 가리키지 않는다. 화면을 못 보는 청자도 알도록 표 · 그림의 이름과 내용을 말로 한다
- 그림은 무엇을 뜻하는지만 한 줄로 말한다. 선 · 점선 · 화살표 · 테두리 같은 그린 방식은 읽지 않고, 앞 문장을 되풀이할 뿐인 그림은 건너뛴다
- 실습은 멈추지 않는다. "잠깐 멈추고 해 보셔도 좋아요"처럼 안내만 하고 `long` 쉼을 둔다
- 핵심어는 동의어로 바꾸지 않고 같은 단어로 되풀이한다. 섹션 끝에 "정리하면" 한 문장
- **화면의 목록 · 표 · 카드를 다 읽지 않는다.** 머리말은 배우는 것 목록을 "먼저 · 그다음 · 마지막으로" 세 덩어리로 묶어 바꿔 말한다(항목이 3개면 하나씩). 본문도 5개 이상 나열은 핵심 2~3개만 짚고 나머지는 묶는다. 요약도 "자, 오늘 내용을 세 가지로 정리해 볼게요." 뒤 첫째 · 둘째 · 셋째 세 줄로 묶는다(강조는 각 묶음의 첫 항목). 세부는 화면에 둔다

## 문체

| 항목     | 규칙                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 종결어미 | 정의 · 요점 · 요약은 합쇼체, 풀이는 해요체. '-죠' · '-거든요'는 한 문단에 한두 번. 군말은 쓰지 않음                                                  |
| 문장     | 한 문장에 한 생각. 공백 뺀 60자 이하(크롬 네트워크 음성이 15초 넘는 발화를 자른다). 관형절이 겹치면 쉼표를 더하지 말고 문장을 나눔                   |
| 도입     | 여는 질문으로 바로 시작(머리 문구 없음) → 짧은 답 → "이 페이지를 마치면 ~할 수 있어요" 약속 한 문장 → "먼저, 그다음, 마지막으로"로 예고              |
| 마무리   | 요약 뒤 여는 질문을 다시 불러 한 줄로 답함 → "이 페이지는 여기까지예요." → 다음 페이지의 여는 질문으로 예고. 인사로 끝내지 않음                      |
| 접속어   | 나열 '그리고', 원인 '그래서', 바꿔 말하기 '그러니까', '그런데'는 반전에만. 문장 첫 접속어 뒤에 쉼표를 찍지 않음                                      |
| 피할 말  | 군말(이제 · 약간 · 뭐), 이중 피동(되어지다 · 보여지다), "~를 가진", "~에 대해 알아보겠습니다", 대시 · 말줄임표. 같은 어미를 세 문장 연달아 쓰지 않음 |
| 전환     | "자, ~", "그럼 ~볼게요"를 단독 문장으로. "자"는 섹션 경계에서만                                                                                      |
| 질문     | 섹션당 한두 개. 뒤에 `think` 쉼(2.5초)을 두고 바로 스스로 답함 (Rowe의 대기 시간 연구)                                                               |
| 용어     | 풀이를 먼저 하고 이름을 붙임                                                                                                                         |

## 쉼 (`pause`)

| 값        | 쓰는 곳                                                    |
| --------- | ---------------------------------------------------------- |
| `flow`    | 나열을 줄마다 나눠 강조를 옮길 때. 한 문장처럼 이어 들린다 |
| `short`   | 보통 문장 경계                                             |
| `long`    | 실습 안내 뒤, 큰 전환 전                                   |
| `think`   | 질문 뒤                                                    |
| `section` | 섹션 끝                                                    |

## 발음

- 약어 · 코드 용어 · 키 이름은 `speech.ts`의 사전에 한 번 등록하고 대본에는 화면 표기 그대로 쓴다. 근거(W3C 용어집 등)는 사전 주석에 남긴다
- `say`는 사전으로 안 되는 문장 단위 표현에만 쓴다. 사전과 같은 내용을 `say`로 반복하지 않는다
- 숫자 사이 점 같은 기호는 사전 규칙이 말로 푼다. 규칙에 없는 기호는 대본 문장을 바꿔 피한다

## 영어 대본

한국어 대본을 옮기지 않고 같은 사실로 새로 쓴다. 위 내용 · 쉼 규칙은 같고 문체만 다르다.

- 여는 말은 흔한 오해나 구체 장면 하나 → 듣는 사람("you")의 경험 → 오늘의 질문
- 전환은 "Now, ..." · "Let's break that down." 같은 짧은 독립 문장. 중요도는 "The point is" 같은 표지로 알린다
- 화면을 가리킬 때는 지시어 + 보이는 것의 이름 + 볼 점을 짝짓는다("Notice that the first row, ...")
- 개념을 쉬운 말로 먼저 보이고 "That is called X"로 이름을 붙인다
- 핵심 순간(여는 말 · 전환 · 용어 도입)은 4~8단어 짧은 문장, 설명은 길게

## 근거

대본을 쓰고 다듬을 때 조사한 자료 가운데 위 규칙을 받치는 것만 남긴다.

- 합쇼체 · 해요체 혼용 — 한국인 대학생 발표 전사 비교 ([한국언어문화학 23(1), 2026](https://scholar.kyobobook.co.kr/article/detail/4010072000055))
- 대화체는 친근감 · 인지 처리에 효과가 있지만 학습량 효과는 약하다. 해설체는 끝까지 듣게 하는 장치이고 이해는 실습 · 표가 맡는다 ([Ginns, Martin & Marsh 2013](https://researchers.westernsydney.edu.au/en/publications/designing-instructional-text-in-a-conversational-style-a-meta-ana/))
- 질문 뒤 약 3초 대기 ([IRIS Center](https://iris.peabody.vanderbilt.edu/wp-content/uploads/misc_media/fss/pdfs/2018/IRIS_fundamental_skill_sheet_wait-time.pdf))
- 담화 표지(전환 · 요점 예고)가 강의 이해를 돕는다 ([Deroey & Taverniers](https://orbilu.uni.lu/handle/10993/17328))
- TTS 대본은 숫자 · 기호 · 괄호를 읽을 말로 풀고, 한 번 정한 읽기를 끝까지 같게 쓴다 ([Typecast](https://typecast.ai/kr/learn/?p=7492))
- 약속 한 문장으로 열고 인사가 아닌 결론으로 닫는다 ([Winston, How to Speak 요약](https://akos.ma/blog/how-to-speak-by-patrick-winston/))
- 화면 글을 그대로 읽으면 학습이 떨어진다(중복 효과). 대본은 바꿔 말한다 ([Diao & Sweller 2007](https://unsworks.unsw.edu.au/entities/publication/c6788b5d-a907-485e-94e1-8d65792e9808))
- 일반 접속어 뒤에는 쉼표를 찍지 않는다 ([국립국어원 문장 부호 해설 기사](https://dhnews.co.kr/news/view/179510989171749))
- 강연은 세부 목표와 요약을 다 읽지 않고 세 덩어리로 예고하고 정리한다(사람이 한 번에 붙잡는 덩어리는 3~4개) ([Carmine Gallo](https://www.carminegallo.com/))
- 크롬 네트워크 음성은 약 15초 넘는 발화를 자른다 ([PhET utterance-queue #60](https://github.com/phetsims/utterance-queue/issues/60))
